# Provider / Model Compatibility Removal Record

This record documents the completed cleanup of the temporary provider/model compatibility adapter.

## Completed

- Removed `src/pp_agent/llm/compat.py`.
- Removed imports and tests for the old legacy conversion helper.
- Removed resolver branches that accepted legacy top-level `provider_id`, `model_provider_id`, or raw `model_id` strings as capability inputs.
- Kept user-facing provider/model configuration fields because they describe model selection, not capability decisions.

## Current Boundaries

- Provider remains the supplier/authentication abstraction: provider id, protocol, base URL, and API key environment variable name.
- `ModelCapabilityProfile` is the internal model capability abstraction.
- `RuntimeProfile` is the Agent turn execution capability abstraction.
- `model_runtime_selected` trace metadata remains the audit surface for provider, model, runtime, model capability summary, and runtime support summary.

## Follow-up Watchlist

- Keep future model capability checks in model profiles or the model registry.
- Keep BotProfile reserved fields separate from capability inference until Bot-specific runtime selection is implemented.
- Keep TraceInspect backward-compatible with old traces that do not include `model_runtime_selected`.
